# Retail Sales and Operations Analysis

Retail transaction analysis and reporting built from the UCI Online Retail dataset. The project includes a Python data pipeline, a PostgreSQL schema and query set, an Excel audit workbook, chart exports, and a Power BI report.

## Data source

The source workbook contains 541,909 invoice-line records dated from 1 December 2010 through 9 December 2011. Dataset: [UCI Machine Learning Repository, Online Retail](https://archive.ics.uci.edu/dataset/352/online%2Bretail). Citation: Chen, D. (2015), *Online Retail*, DOI [10.24432/C5BW33](https://doi.org/10.24432/C5BW33). License: CC BY 4.0.

## Data preparation

`prepare_dashboard.py` removes exact duplicate rows, cancellation invoices, invalid dates, and rows with non-positive quantity or unit price. IQR bounds are reported as diagnostics; flagged rows remain in the sales totals because large wholesale orders can be valid.

The main sales table is at invoice-line grain. The supporting dimensions cover date, product, customer, and country. Product descriptions are standardized to the most frequent description for each stock code, keeping `dim_product.stockcode` unique. Sales lines without a customer ID remain in revenue totals and are excluded from customer-level measures.

The cleaned data contains 524,878 sales lines, 19,960 invoices, 4,338 identified customers, and £10,642,110.80 in positive line sales. December 2011 is partial because the source ends on 9 December.

## Reports

`Retail-Operations-Dashboard-Updated.pbix` contains one overview page with revenue by country, a monthly revenue trend, and a known-customer sales KPI. The model includes `fact_orders`, `fact_sales`, `dim_date`, and `dim_country`. Active relationships link `fact_sales[invoice_date]` to `dim_date[date]`, `fact_orders[country]` to `dim_country[country]`, and `fact_sales[invoiceno]` to `fact_orders[invoiceno]`. The direct relationship from `fact_sales[country]` to `dim_country[country]` is inactive. `dim_product` and `dim_customer` are available as CSV files but are not loaded in this PBIX, so the saved model is a partial reporting model rather than a complete star schema.

`reports/retail_audit.xlsx` is a static audit workbook with monthly sales and data-quality summaries. The four PNG charts in `reports/figures/` are generated by the Python pipeline. `reports/analysis_summary.json` and `reports/cleaning_log.csv` contain the cleaning and summary metrics.

## Project files

- `prepare_dashboard.py` — data cleaning, table preparation, and chart generation.
- `Retail-Operations-Dashboard-Updated.pbix` — saved Power BI report and model.
- `data/processed/fact_sales.csv` — cleaned invoice-line sales table.
- `data/processed/dim_*.csv` — date, product, customer, and country dimensions.
- `data/processed/fact_orders.csv` — customer-linked invoice summaries used in the Power BI file.
- `data/processed/product_sales.csv` — product-level revenue, units, and order counts.
- `sql/analytics.sql` — PostgreSQL schema and analysis queries.
- `powerbi/DAX_measures.md` — DAX measures for the full `fact_sales` model and the measure in the included report.
- `reports/retail_audit.xlsx` — monthly sales and data-quality audit.
- `reports/figures/` — monthly sales, seasonality, cohort-retention, and product charts.

If the raw workbook is missing, the Python pipeline retrieves it from UCI. Raw and processed data are excluded from Git by `.gitignore`; both are present in the supplied project ZIP.
